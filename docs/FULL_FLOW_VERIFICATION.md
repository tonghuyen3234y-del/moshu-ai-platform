## 本次修复

1. **全新目录无法启动**：默认 SQLite 路径的父目录缺失时，首次启动报 `unable to open database file`。`init_db` 现在在连接前建立普通 SQLite 文件的父目录，并保留内存数据库及 SQLite URI 处理。新增回归测试验证嵌套目录和重复初始化。
2. **首次发布响应丢失版本信息**：新版本创建后，当前 SQLAlchemy 会话中的版本集合仍为空，使发布响应的 `published_version` 为 null，页面提示“已发布 v”。发布完成后刷新版本集合，补充回归断言验证首次发布即返回正确版本和版本列表。
3. **集成测试无法在全新 PostgreSQL 上执行**：测试直接写模型时引用了不存在的默认工作空间。改为创建独立测试工作空间并在测试完成时清理。

## 验收边界

- 本轮没有接入真实付费模型；模拟回答及确定性测试向量仅证明系统链路，不能证明回答质量或真实语义检索效果。
- 实际浏览器业务链路使用 SQLite + inline；Docker 测试验证 PG/Redis/S3 的直接交互，未启动 Celery Worker 验证异步队列端到端。
- 针对当前页面验收实例的额外在线 v2 发布/回滚/下线恢复、临时 API Token 与分享链接验收脚本，被自动审批拒绝，尚未执行；这些能力已有自动化测试覆盖。
- 集成测试结束后已停止本次创建的三个验证容器，保留数据卷；前端 4174 和 API 8001 保持运行。
- 本轮未进行生产部署。
